# Reidom 效果器与插件宿主边界

## 当前可用

基础版 DAW 直接提供四个轨道内置效果器：

- 三段均衡
- 压缩器
- 延迟
- 混响

它们由 JUCE DSP/音频模块在引擎内处理，支持实时播放、WAV 渲染、工程保存/恢复和撤销/重做。处理器在音频设备启动时预分配状态和延迟缓冲区，音频回调中不扫描插件、不创建对象，也不分配内存。

工程快照能力标记：

- `builtin_track_effects: true`
- `plugin_hosting: false`

因此界面只展示真实可用的内置效果，不把第三方插件入口伪装成已完成能力。

## JUCE 能提供什么

JUCE 提供构建插件宿主所需的底层 API，包括：

- `AudioPluginFormatManager`
- `KnownPluginList`
- `AudioPluginInstance`
- VST3 / AudioUnit 等格式适配
- 插件参数、状态块、延迟与尾音信息

JUCE 不会自动提供完整的产品级插件系统。插件目录管理、隔离扫描、崩溃恢复、黑名单、工程状态、自动化和界面承载仍需要 Reidom 自己实现。

## 第三方 VST3 的建议结构

```text
engine/
  audio/
    TrackEffects.*          # 已实现：基础内置效果链
  plugins/
    PluginCatalog.*         # 插件元数据与缓存
    PluginGraph.*           # 每轨实例、顺序、旁路、延迟
    PluginState.*           # 工程序列化与状态块
    ScannerClient.*         # 与隔离扫描进程通信
apps/
  plugin-scanner/           # 独立进程；扫描崩溃不拖垮 DAW
```

扫描进程只负责发现和验证插件，将稳定 ID、格式、路径、输入输出布局和扫描结果写入缓存。主引擎只从已验证目录创建实例。

## 命令与工程模型

后续宿主使用独立命令族，不复用 `effects.set_state`：

- `plugins.scan`
- `plugins.add`
- `plugins.remove`
- `plugins.reorder`
- `plugins.set_bypass`
- `plugins.set_parameter`

工程中每个实例至少保存：

- 稳定插件 ID、格式和版本
- 所属轨道与链中顺序
- 旁路状态
- 插件状态二进制块
- 自动化参数映射
- 缺失插件占位信息

加载工程时插件缺失不应阻止工程打开；保留占位和状态，允许用户稍后重新定位。

## 实时与可靠性要求

- 插件扫描永远不进入音频进程的实时回调。
- 插件实例创建、销毁和状态恢复在控制线程完成，再原子切换音频图。
- 插件报告的延迟参与轨道延迟补偿。
- 插件崩溃或扫描超时进入隔离/黑名单，并提供可诊断记录。
- 保存工程时状态块有大小上限和失败提示。
- 首版先支持轨道插入效果；乐器插件、多输出和侧链作为后续能力。

## 接入顺序

1. 保持当前内置效果满足基础创作和导出。
2. 增加独立扫描进程、插件缓存和缺失插件占位。
3. 接入轨道 VST3 插入链、保存恢复和旁路。
4. 再增加参数自动化、延迟补偿、侧链和多输出。

这个边界让基础版保持轻量，同时为第三方插件保留可扩展但不会污染实时音频线程的路径。
